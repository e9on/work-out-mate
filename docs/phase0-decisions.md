# Phase 0 진행 중 내린 판단과 Phase 2로 넘길 일

- 기간: 2026-11-18
- 브랜치: `feat/phase0-core`
- 이 문서는 작업 중 진행 장부(`.superpowers/sdd/…/progress.md`, git 제외)에 있던 판단 기록을 옮긴 것이다. 장부는 브랜치를 마무리하며 지운다.

## 1. 사용자가 정한 것
- MVP는 루틴 전체(B안). 운동은 푸시업, 덤벨 벤치프레스, 스쿼트, 턱걸이(매달리기·네거티브·턱걸이)
- 루틴은 사용자가 이름을 붙인다(푸시데이·풀데이·하체데이). "N일차" 대신 쓴다.
- 정확도 기준: 10회 세트에서 ±1회, 매달리기는 ±1초
- 덤벨 벤치프레스는 양팔 동시. 기준 기기는 갤럭시 S23
- 턱걸이는 팔 각도로만 판별한다.
- 실시간 기반으로 동작한다. 녹화 재생은 테스트 도구로만 쓴다.
- 실패하는 테스트를 먼저 쓰고 RED를 확인한 다음 고친다.
- 준비 자세를 기준으로 보정한다(스쿼트·푸시업·벤치).
- 매달리기 기준값은 앱 측정값(13.8초)으로 한다.
- PC 앱은 Tauri 대신 Electron으로 만든다.
- Android·iPhone은 앱으로 만들고, iPhone은 나중에 추가한다.

## 2. 구현하면서 대신 내린 판단 (틀렸을 때의 비용)
| 판단 | 이유 | 틀렸을 때 |
|---|---|---|
| NaN 각도는 null로 바꿔 EMA에 넣음 | EMA가 NaN 한 번에 영구 오염됨 | 실시간 카운터가 멈춤 (테스트로 막음) |
| 매달리기 시작 전 1프레임 깜빡임에 후보 폐기 | 계획 시나리오와 일치 | 매달리기 시작이 늦게 잡힐 수 있음 |
| 좌우 팔·다리를 프레임마다 선택(히스테리시스 없음) | 계획대로 | 측면 촬영에서 신호가 튈 수 있음 |
| 구간별 최소 시간 → 반복 전체 최소 시간(500ms) | 실측에서 150→100° 구간이 0.19~0.23초 | 0.5초 미만의 빠른 진짜 반복을 놓침(실측 1.3~1.6초) |
| 재무장(armed): 시작 자세를 지나야 다음 반복 | 가렸다가 중간 자세로 돌아와도 세지 않게 | 시작 자세를 덜 지나는 사람은 첫 반복을 놓침 |
| 네거티브는 바닥 도달 시 즉시 셈(countAt 'turn') | 위로 가는 동작은 점프라 마지막 반복이 안 세졌음 | 풀업형 재무장 로직에 영향 |
| 풀업·네거티브는 양팔 평균 각도 | 한쪽 팔이 덜 펴진 값으로 잡혔음 | 한쪽 가시성이 깜빡이면 신호가 급변할 수 있음 |
| 네거티브 100/140/95, 최소 250ms | 실측(녹화 1개) | 착지 흔들림을 셀 위험. 추가 녹화로 재확인 |
| 푸시업 고정값 145/120/150 → 6b로 대체 | 실측 위 155~157, 바닥 90~114 | — |
| 6b 재무장선 base − depth/2 | 확정 직후 흔들림 2회 카운트 방지 | 반쯤만 펴고 연속하는 반복을 놓침 |
| 6b 보정 타임아웃은 구간이 마지막으로 비워진 뒤부터 | 잠깐 보인 순간부터 재는 문제 | — |
| 6b 준비 자세 확인 ready(frame) | 서서 걸어올 때 푸시업 기준이 잡히는 문제 | 정면 촬영은 영원히 보정 중 |
| Android 녹화는 Documents, 실패 시 앱 전용 폴더 | Android 10+ 저장 제한 대비 | — (S23에서 Documents 성공) |
| Android INTERNET 권한 제거, allowBackup=false | 네트워크 0건·클라우드 없음을 OS 수준에서 보장 | 라이브 리로드 불가 |
| 합격 테스트 두 기준(사람 ±1, replay 정확값) | 5회 세트에서 ±1은 20% 허용 | deadHang 정확값은 부동소수 잡음에 민감할 수 있음 |

## 3. Phase 2 선행 작업 (최종 검토 Important)
1. **세트 종료 직전 반복 되돌리기**: 기기를 조작하러 다가가며 몸을 굽힌 동작이 1회로 세진다. 6회로 센 녹화 2건이 모두 이 경우다.
2. **보정 실패 대응**:
   - 타임아웃 때는 고정 기본값 대신 보정 구간에서 관측한 최고점을 쓴다.
   - `TrackerState`에 왜 안 세는지(`calibrationSource`, `readyFailing`)를 실어 UI가 "옆에서 찍어 주세요"를 띄우게 한다.
3. **몸통 기울기를 world 좌표로 계산한다**: 정규화 image 좌표는 화면 비율에 따라 허용 범위가 바뀐다.
4. **RepCounter와 AdaptiveRepCounter를 공통 껍데기 하나로 합친다**: `TrackerState`도 판별 유니온으로 바꾼다.
5. **CSP `connect-src 'self'`**: 모든 실행 환경에서 같은 네트워크 방어선을 둔다.
6. **덤벨 벤치프레스 측면 촬영 실측**: 양팔이 모두 보여야 신호가 나와서 0회가 될 위험이 있다. 실측한 뒤 `meanVisibleArms`로 바꿀지 정한다.
7. **10회 세트 녹화로 spec 기준을 다시 확인한다**: 지금 녹화는 모두 5회 세트다.
