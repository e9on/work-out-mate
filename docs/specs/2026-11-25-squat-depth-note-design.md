# 스쿼트 깊이: 오류 지적 → 세트 조언 (3D 각도) — 설계

- 날짜: 2026-11-25
- 브랜치: `feat/form-analysis` (PR #14 위에 이어서)

## 1. 왜

- **사용자 결정 (2026-11-25)**: 덜 앉은 것은 오류로 두지 않는다. "스쿼트를 덜 앉았다" 같은 피드백으로 보여 준다. 하프 스쿼트도 정상적인 운동 방식이고, 얼마나 깊이 앉을지는 사람마다 다르다.
- **측정 문제: 지금 깊이 판정은 RTMPose 2D 무릎 각도 100° 기준이고, 45° 촬영에서 양쪽으로 틀린다.**

| 녹화 | 2D 판정 결과 | 3D 각도 |
|---|---|---|
| 정상 반복 2회 (diag45) | 2D 105°·106°로 잘못 지적 | 54°·49° |
| 하프 스쿼트 10회 (2026-11-25, 45°) | 4회만 잡음 (2D 93~107°) | 77~94° |

- **3D(MediaPipe world) 무릎 각도는 지금까지 녹화를 모두 갈랐다.**
  - 정상: 38~65°
  - 경계(허벅지 수평 바로 위): 50~68°
  - 하프: 77~94°

## 2. 무엇을 바꾸나

1. **3D 바닥 각도 기록**
   - 반복 카운터는 이미 운동 중 MediaPipe world 좌표로 무릎 각도를 신호로 쓴다. 더 잘 보이는 쪽 다리를 쓰고, 평활을 거친 값이다.
   - 이 신호의 반복별 최저점(`RepEngine`의 valley)을 `RepEvent`에 싣는다.
   - 세트 기록의 반복 시각(`RepTiming`)에 선택 필드 `bottomKneeDeg`로 저장한다.
   - 예전 기록에는 이 값이 없다. 그 세트는 깊이 조언을 내지 않는다.
2. **깊이는 지적(findings)에서 빼고 세트 조언(notes)으로 옮긴다**
   - 새 `SetNote`: `{ kind: 'shallow', count, total }`
   - 판정: `bottomKneeDeg > SQUAT_RULES.shallowKneeDeg3d`인 반복을 센다. 1회 이상이면 조언을 낸다.
   - `total`은 3D 값이 있는 반복 수다.
   - 문구(ⓘ, 지금의 '빨리 내려감' 조언과 같은 자리·모양): `이번 세트는 {total}회 중 {count}회를 덜 앉았어요. 허벅지가 바닥과 평행해질 때까지 앉아 보세요`
   - 반복별 지적 목록과 반복 재생 화면의 자동 지적에서는 깊이가 사라진다.
   - 사용자가 직접 고르는 수동 오류 라벨 '깊이 부족'은 그대로 둔다(학습 데이터용).
3. **무릎 모임 판정 조건**
   - 지금은 2D로 얕다고 본 반복은 무릎 모임 판정을 건너뛴다.
   - 바꾼 뒤: 3D 값이 있으면 3D 기준으로 건너뛴다. 없으면 지금처럼 2D로 건너뛴다.
4. **기준값 `shallowKneeDeg3d`**
   - 앱 카운터와 똑같은 신호(한쪽 다리, 평활)로 다시 잰다. 개인 녹화를 core의 replay로 돌려 반복별 valley를 뽑는다.
   - 대상 녹화: diag45-12, diag45, 2026-11-25의 세 세트
   - 정상·경계의 최댓값과 하프의 최솟값 사이 가운데로 정한다.
   - 분석에서 쓴 두 다리 평균·중앙값과 값이 조금 다를 수 있어서 이 과정을 따로 둔다.
   - 예상은 약 70°. 경계 반복은 조언 대상이 아니게 한다(수평 근처까지는 봐준다).

## 3. 비목표

- 깊이 목표를 사용자가 고르는 설정(풀/하프)
- 다른 운동의 깊이
- RTMPose 2D 기반 다른 판정(무릎 모임·뒤꿈치)의 각도 보정

## 4. 시험

- **core 단위 시험**
  - valley가 RepEvent·RepTiming에 실리는지
  - 조언 생성(0회면 없음, count·total)
  - 깊이가 findings에 나오지 않는지
  - 3D 값으로 무릎 모임 판정을 건너뛰는지, 3D 값이 없으면 2D로 대신하는지
- **기준값 확인 시험**: 개인 녹화가 있을 때만 돈다. 정상·경계 반복은 조언 0회, 하프 10회는 모두 조언에 들어가야 한다.
- **앱 화면 시험**: 조언 문구가 ⓘ 줄로 나오는지

## 5. 위험

- 한 사람, 한 위치, 세 세션에서 정한 기준값이다.
- MediaPipe lite의 3D 값도 추정이다. 정면 촬영에서 무릎 점이 튀는 문제가 알려져 있다(R7).
- 카운터 신호는 평활을 거친 값이라 실제 최저보다 조금 높게 나올 수 있다. 기준값을 같은 신호로 정하므로 앱 안에서는 일관된다.
