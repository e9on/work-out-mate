## 0. 왜 만드는가

지금 앱은 횟수와 시간만 센다. 사용자는 운동이 끝난 뒤 **"어디가 부족했는지"**를 알고 싶어 한다. 예를 들면 "2세트 4번째 반복(0:18)에서 무릎이 안으로 모였어요" 같은 안내다. 그리고 그 순간을 **실제 영상으로 다시 보고** 싶어 한다. [확정]

사용자는 운동하는 동안 지적받는 것이 아니라, 운동이 끝난 뒤 결과 화면에서 돌아보는 것을 원했다. [확정]

## 1. 범위

### 목표
1. 세트를 하는 동안 카메라 영상을 폰 안에만 녹화한다. [확정]
2. 세트가 끝나면 저장한 영상을 정확도가 높은 모델(MediaPipe **heavy**)로 다시 분석한다. [확정: 시험 뒤 결정]
3. 반복마다 자세 오류를 판정하고, 운동 결과 화면과 기록 상세 화면에 "몇 세트, 몇 번째 반복, 영상 몇 초, 무엇이 문제인지"를 보여 준다. [확정]
4. 지적 항목을 누르면 그 순간의 영상으로 이동해서 재생한다. 영상 위에 관절 선을 겹쳐 보여 주고, 켜고 끌 수 있다. [제안]
5. 영상 보관: **루틴마다 최근 3회는 전체 영상**을 남긴다. 그보다 오래된 기록은 **지적이 나온 반복 앞뒤 구간만** 남긴다. [확정]
6. 처음 대상 운동은 **스쿼트** 하나다. 다른 운동은 같은 구조에 판정 규칙만 더하는 식으로 나중에 넓힌다. [제안]

### 스쿼트 지적 항목 [확정: 논문 조사와 시험 뒤 결정]
| 항목 | 반복마다 / 세트 요약 | 처음 버전에 넣음 |
|---|---|---|
| 깊이 부족 | 반복마다 | ✅ |
| 무릎이 안으로 모임 | 반복마다 | ✅ |
| 너무 빨리 내려감 | **세트 요약으로 한 번** (반복마다 지적하면 잔소리가 된다) | ✅ |
| 뒤꿈치 들림 | — | ❌ 세 모델 모두 측정 실패 |
| 골반 좌우 기울어짐 | — | ❌ 바른 자세에서도 값이 크게 흔들림 |
| 무릎이 발끝을 넘음 | — | ❌ **지적하지 않는다**. 오류가 아니라는 근거가 있다(9절) |
| 허리 말림, 머리·가슴 자세 | — | ❌ 관절점으로 재기 어렵고 근거도 엇갈림 |

### 하지 않는 것 (non-goals)
- 운동 중 실시간 자세 지적(음성·화면). 이번에는 운동 뒤 결과 화면에서만 보여 준다.
- 서버·클라우드 처리, 영상 업로드. 영상과 관절 좌표는 폰 밖으로 나가지 않는다.
- 자체 ML 모델 학습. 이번에는 MediaPipe 관절점과 각도 규칙으로 판정한다.
- 운동 12종 추가(바벨 벤치프레스, 딥스 등). 이 작업이 끝난 뒤 **별도 프로젝트**로 한다.
- PC(Electron)에서의 동작 보장. 웹 코드라 돌아갈 수는 있지만 목표가 아니다. 사용자가 PC 앞에서 운동하지 않는다.

### 실패로 보는 것 (anti-goals)
- **틀린 지적.** 잘못 지적하는 것은 지적하지 않는 것보다 나쁘다. 정확도를 재서 기준을 넘은 항목만 내보낸다(8절).
- 운동 흐름을 방해하는 것. 분석이 늦어져도 횟수 세기, 쉬는 시간, 음성 안내가 느려지면 안 된다.
- 영상이 폰 밖으로 나가는 것. 네트워크 요청 0건 원칙을 지킨다.

## 2. 제약

- **네트워크 0건, 서버 없음.** 기존 원칙을 그대로 따른다. Android INTERNET 권한 없음, allowBackup=false, CSP 유지.
- 기준 기기: 갤럭시 S23. 앱은 Capacitor WebView에서 돈다.
- 실시간 횟수 세기는 지금처럼 **lite** 모델로 한다. 바꾸지 않는다.
- 측정된 S23 속도는 Chrome, GPU, 1080×1920 영상 기준 프레임당 lite 30ms, full 36ms, **heavy 66ms**다. 30초 세트(900프레임)를 heavy로 전부 분석하면 약 60초가 걸린다.
- 영상과 관절 좌표는 개인 신체 데이터다. 앱 전용 저장소에만 두고 갤러리에는 넣지 않는다. [제안]
- 기존 기록(WorkoutSession)과 호환돼야 한다. 영상이 없는 옛 기록도 지금처럼 보여야 한다.

## 3. 촬영 방법 [확정: 시험 뒤 결정]

- **45도 한 방향.** 폰을 몸 앞쪽 대각선, 허리 높이에 두고 머리부터 발끝까지 여유 있게 나오게 한다.
  - 옆에서는 무릎 모임이 안 보이고, 정면에서는 손이 골반을 가릴 때 무릎 점이 튄다. 45도가 둘 다 가장 나았다(10절).
- 배치 안내 화면(Placement)을 운동별로 바꾼다. 스쿼트는 "45도, 허리 높이, 발끝까지 화면에"로 안내한다.
- 옷차림 안내를 추가한다.
  - **무릎 윤곽이 보이는 옷**(반바지나 몸에 붙는 운동복 바지)
  - **신발은 평소대로 신어도 된다** [확정]. 맨발일 필요는 없다.
  - 팔은 앞으로 뻗거나 가슴 앞에 모은다(골반을 가리지 않게).
- 이 안내는 처음 몇 번만 보여 주고, "다시 보지 않기"를 둔다. [제안]

## 4. 전체 흐름

```
세트 시작 ─▶ 영상 녹화 시작 (lite 실시간 세기는 지금 그대로)
세트 끝   ─▶ 녹화 종료, 영상 파일 저장 (세트당 파일 1개) [제안]
         ─▶ 분석 대기열에 넣음
쉬는 시간 ─▶ 대기열을 heavy로 분석 (실시간 세기와 음성은 늘 우선)
루틴 끝   ─▶ 남은 분석을 계속하고, 결과 화면에 "분석 중…" → 끝나면 지적 목록을 채움
기록 상세 ─▶ 지적 목록 → 누르면 해당 시각으로 영상 재생
```

### 4.1 반복 목록은 실시간 카운터를 기준으로 한다 [제안]
- "4번째 반복"은 사용자가 운동 중에 들은 숫자와 같아야 한다. 그래서 **분석은 반복을 새로 찾지 않는다.** 실시간 카운터(lite)가 확정한 반복의 시작·끝 시각을 그대로 쓰고, 그 구간 안에서 heavy 관절점으로 지표만 계산한다.
- 이를 위해 기록(SetLog)에 **반복마다 시작·바닥·끝 시각**을 추가로 저장한다. 지금 SetLog에는 반복 시각이 없다. 기존 기록은 이 필드가 없어도 읽혀야 한다.
- 영상의 시작 시각과 세트 시각을 같은 시계로 맞춰 둔다. 그래야 "반복 시각 → 영상 몇 초"로 바꿀 수 있다.

### 4.2 분석 속도 [제안]
- 영상을 **15fps로(한 프레임씩 건너뛰며)** 분석한다. 30초 세트면 약 30초다. 깊이와 무릎 각도는 1초에 15장이면 충분하다.
- 분석은 쉬는 시간에 한다. 다 못 끝내면 다음 쉬는 시간이나 루틴이 끝난 뒤에 이어서 한다.
- 앱이 중간에 꺼져도 다음에 열었을 때 남은 분석을 이어서 한다. [제안]
- 실시간 세기(lite)와 heavy 분석을 동시에 돌릴 때의 성능은 **[확인 필요]**이다. 세기가 밀리면 분석을 멈춘다.

## 5. 판정 규칙 (스쿼트)

공통 전처리 [제안]
- heavy의 world 좌표(미터 단위 3D)를 쓴다.
- 인식이 틀린 프레임을 버린다. 관절이 안 잡힌 프레임이나, 허벅지·정강이 길이가 그 세트의 중앙값과 크게 다른 프레임이다.
- 반복의 바닥 시각 앞뒤 150ms 구간의 **중앙값**으로 판정한다. 한 프레임 값으로 판정하지 않는다.
- 양쪽 다리 값을 함께 본다. 한쪽 다리만 굽힌 동작(발 옮기기)은 반복으로 세지 않는다. 이건 실시간 카운터의 몫이지만, 분석에서도 한쪽만 굽은 구간은 판정하지 않는다.

### 5.1 깊이 부족
- 지표: 바닥에서의 무릎 안쪽 각도(엉덩이–무릎–발목, 양쪽 평균).
- 기준: 허벅지가 바닥과 최소 평행(평가표 9번). 시험에서는 일부러 얕게 앉은 반복이 69~99°, 나머지가 60° 이하였다. **처음 기준값은 65°**로 둔다. 이 값보다 크면 "깊이 부족"이다. [제안, 확인 필요]
- 문구 예: "4번째: 허벅지가 바닥과 평행해질 때까지 앉지 않았어요"

### 5.2 무릎이 안으로 모임
- 지표: 바닥에서의 **무릎 간격 ÷ 골반 간격**(3D).
- 사람마다 값이 크게 다르다(바른 자세가 녹화에 따라 1.7~2.6). 그래서 **본인의 바른 자세와 비교**한다.
- 깊이가 얕으면 원래 무릎이 덜 벌어진다. 그래서 바른 자세 값을 **깊이(무릎 각도)에 맞춰** 비교한다.
- 바른 자세 등록 [제안]
  - 처음 자세 분석을 켤 때 "바른 자세로 3회"를 한 번 녹화해 등록한다. 다시 등록할 수도 있다.
  - 등록한 반복으로 "무릎 각도 → 바른 무릎 간격 비율"을 만든다. 예를 들면 직선 근사다.
  - 등록 전에는 이 항목을 판정하지 않는다.
- 기준: 관측값 < 예상값 × **0.85**면 지적한다. 0.85는 시험 데이터 4건으로 고른 임시값이다. [제안, 확인 필요]
- 참고 기준(평가표 5번): 무릎이 복사뼈 안쪽 선을 넘으면 심한 경우다. 이번 시험에서는 한 번도 해당되지 않았다. 가벼운 모임을 잡으려면 상대 비교가 필요하다.
- 문구 예: "6번째: 무릎이 안으로 모였어요"

### 5.3 너무 빨리 내려감 (세트 요약)
- 지표: 반복마다 내려가는 시간(서 있는 각도에서 15° 내려간 시점부터 바닥까지)과 올라오는 시간.
- 기준: 내려가는 데 2~3초를 권장한다(Schoenfeld 2010). 평가표는 내려가는 시간이 올라오는 시간의 2배 이상이어야 한다고 본다(Myer 2014).
- 세트 평균 내려가는 시간이 **1초 미만**이면 세트 요약에 한 줄로 알려 준다. [제안]
  - 예: "이번 세트는 평균 0.6초 만에 내려갔어요. 2초 이상 천천히 내려가 보세요"
- 사용자가 평소에도 0.6~0.8초에 내려가서, 반복마다 지적하면 모든 반복이 걸린다. 그래서 요약으로만 알려 준다.

### 5.4 판정하지 않는 것을 화면에 쓰지 않는다
- 무릎이 발끝을 넘는 것은 지적하지 않는다. 다만 "이번 세트는 엉덩이 위주 / 무릎 위주였어요" 같은 참고 정보로 보여 줄지는 나중에 정한다.

## 6. 화면

### 6.1 운동 결과(Summary)와 기록 상세(SessionDetail)
```
스쿼트 2세트  10회  ✓ 목표 달성
  ⚠ 4번째 (0:18)  무릎이 안으로 모였어요      ▶
  ⚠ 9번째 (0:41)  깊이가 부족했어요          ▶
  ⓘ 평균 0.6초 만에 내려갔어요. 2초 이상 천천히
스쿼트 3세트  8회   분석 중… (2/3)
```
- 지적이 없는 세트는 "자세 지적 없음"으로 보여 준다.
- 분석하지 못한 세트(영상 없음, 사람이 안 보임, 바른 자세 미등록)는 이유를 한 줄로 쓴다.
- ▶을 누르면 영상 재생 화면이 열린다.

### 6.2 영상 재생
- 해당 반복 시작 1초 전부터 재생한다.
- 관절 선 겹치기를 켜고 끌 수 있다.
- 느리게 보기(0.5배)를 둔다. [제안]
- 영상이 지워진 반복은 "영상이 삭제됐어요(오래된 기록은 지적 구간만 보관)"라고 안내한다.

### 6.3 설정
- 영상 저장 켜기/끄기. 끄면 자세 분석도 하지 않고 지금처럼 횟수만 센다. [제안]
- 바른 자세 다시 등록하기.
- 영상 전체 삭제, 기록마다 영상 삭제.
- 영상이 차지하는 용량 표시. [제안]

## 7. 저장

- 영상: 세트마다 파일 1개. 앱 전용 저장소에 둔다. [제안]
- 보관 규칙 [확정]
  - 루틴마다 최근 3회 기록은 전체 영상을 남긴다.
  - 그보다 오래된 기록은 **지적이 나온 반복의 앞뒤 구간(예: 반복 시작 1초 전 ~ 끝 1초 후)**만 남기고 나머지는 지운다.
  - 정리는 새 기록이 저장된 뒤에 한다.
- 분석 결과(반복별 지표, 지적 목록, 분석에 쓴 heavy 관절 좌표)는 기록에 붙여 저장한다. 관절 선 겹치기에 관절 좌표가 필요하다.
- 예상 용량: 영상은 세트(30초)당 대략 5~10MB다. 루틴 하나(15세트)면 100MB 안팎이다. 루틴이 2~3개면 전체 영상으로 0.6~1GB가 늘 남아 있다.

## 8. 합격 기준

1. **정확도** (사용자 본인 영상, 45도, 무릎이 보이는 옷과 운동화)
   - 바른 자세, 무릎 모으기, 얕게 앉기, 빨리 내려가기가 섞인 20회 영상에서 다음을 만족해야 한다.
     - 깊이 부족과 무릎 모임: 일부러 만든 오류 반복을 **모두** 지적한다.
     - 바른 자세 반복 중 잘못 지적한 것이 **1회 이하**다.
   - 기준을 넘지 못한 항목은 내보내지 않는다(설정에서 숨김). 
2. **속도**: S23 앱에서 30초 세트 분석이 다음 세트가 시작되기 전(쉬는 시간 60초 기준)에 끝난다. 분석 중에도 실시간 세기가 프레임을 놓치지 않는다.
3. **보관**: 4회째 기록이 저장되면 1회째 기록 영상이 지적 구간만 남는다. 지운 구간을 누르면 안내 문구가 나온다.
4. **개인정보**: 네트워크 요청 0건(자가 점검 유지), 영상이 갤러리에 나타나지 않는다, 백업에 포함되지 않는다.
5. **호환**: 영상과 반복 시각이 없는 기존 기록도 지금처럼 열린다.

## 9. 근거 자료 요약

- Myer 등 2014, 스쿼트 평가표(10개 항목) [PMC4262933]: 몸통과 정강이가 나란함, 무릎이 복사뼈 안쪽 선을 넘지 않음, 발 전체가 바닥에 닿음, 허벅지가 최소 평행, 내려가는 시간이 올라오는 시간의 2배 이상. 무릎 전진은 뒤꿈치가 붙어 있으면 제한하지 말라고 한다.
- Straub & Powers 2024 리뷰 [PMC10987311]: 몸통과 정강이 기울기는 엉덩이와 무릎 부하를 맞바꾼다. 몸통–정강이 각도가 −8°면 엉덩이와 무릎 부하가 비슷하다. 최적 스탠스는 정해져 있지 않다.
- Fry 2003: 무릎 전진을 막으면 엉덩이 토크가 크게 늘었다(7명, 작은 연구).
- 무릎 외반 연구: 서 있을 때보다 10° 이상 안으로 꺾이면 외반으로 본다. 2D 측정의 신뢰도는 괜찮지만 3D와 비교하면 정확도에 한계가 있다.
- Schoenfeld 2010: 내려가는 데 2~3초를 권장한다. 피로하면 자세가 무너진다.
- 2013 Sports Medicine 리뷰: 깊은 스쿼트가 연부조직 부상 위험을 늘리지 않는다.

## 10. 시험 결과 요약 (2026-11-24, 사용자 본인)

- 관절 좌표 녹화(lite) 5건: 옆, 45도, 정면, 45도 12회(바른 자세·무릎 모으기·무릎 앞으로 각 4회).
- 영상 1건(71초, 20회): 바른 자세, 무릎 모으기, 뒤꿈치 들기, 빨리 내려가기, 얕게 앉기를 각 4회씩 하고, 같은 영상을 lite/full/heavy로 분석.
- 결과
  - 45도가 무릎 모임과 앞뒤 움직임을 함께 보기에 가장 나았다. 정면은 손이 골반을 가릴 때 무릎 점이 튀었다.
  - 깊이와 무릎 모임은 **heavy에서만** 깔끔하게 갈렸다. full은 lite보다 나은 점이 없었다.
  - 뒤꿈치 들림은 세 모델 모두 잡지 못했다. 골반 기울기는 잡음이 컸다.
  - 영상 속 옷차림(헐렁한 긴 바지, 슬리퍼)이 무릎과 발목 윤곽을 가렸다. 운동화와 운동복 바지로는 아직 시험하지 않았다. **[확인 필요]**
- 기준값(65°, 0.85, 1초)은 한 사람의 적은 데이터로 잡은 임시값이다.
- 녹화와 영상은 git 밖(`packages/core/test/fixtures/private/angle-test/`, `apps/spike/public/mediapipe/bench/`)에만 있다.

## 11. 빌더에게 맡기는 것

- 영상 녹화 방식(MediaRecorder 형식·비트레이트)과 저장 위치(IndexedDB Blob 또는 Capacitor 파일 시스템)
- 오래된 기록에서 지적 구간만 남기는 방법(다시 인코딩할지, 처음부터 반복 단위로 잘라 저장할지 등). 단, 7절 보관 규칙과 8절 합격 기준을 지켜야 한다.
- 분석 대기열 구현, 15fps 추출 방식, heavy 모델을 실시간 lite와 함께 올리는 방식
- 판정 규칙의 코드 구조. 다른 운동을 쉽게 더할 수 있게 한다.
- 화면 세부 디자인
- 새 의존성이 필요하면 다운로드 전에 사용자 허락을 받는다. heavy 모델 파일은 이미 받아 두었다(`apps/spike/public/mediapipe/pose_landmarker_heavy.task`, git 제외).
