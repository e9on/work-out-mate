# Phase 0 측정 결과

- 날짜: 2026-11-18
- 측정한 사람: 사용자 본인 1명
- 기기: 갤럭시 S23 (SM-S911N, Android 16, Android System WebView 157)
- 모델: pose_landmarker **lite** (float16), 처리 장치 **GPU**
- 실기기 숫자는 사용자가 화면에서 읽어 준 값이고, 녹화 분석은 `packages/core`의 replay로 확인한 값이다.

## 1. 속도

| 환경 | FPS(처리) | 추론 평균 | 비고 |
|---|---|---|---|
| S23 앱 (Capacitor WebView, GPU, lite) | 30 | 24ms | 녹화 분석: 29.9fps, 프레임 최대 간격 64ms |
| S23 Chrome 브라우저 (dev:lan, lite) | 30 | 미측정 | 녹화 분석: 30.0fps, 최대 간격 59ms |
| PC 웹캠 | — | — | 웹캠으로 전신이 담기지 않아 측정 못 함 |

- 30fps에서 한 프레임에 쓸 수 있는 시간은 33ms다. 24ms면 시간 안에 들어오지만 여유가 약 9ms뿐이다. 발열이나 백그라운드 부하가 생기면 프레임을 건너뛸 수 있다.
- full 모델, CPU 처리는 아직 측정하지 않았다.

## 2. 기능 확인 (S23 앱)

| 항목 | 결과 |
|---|---|
| 카메라 권한 | 첫 실행에 권한 창이 뜨고, 허용하면 동작 |
| 오프라인 | 앱에 INTERNET 권한이 없는 상태로 자세 인식이 동작함. wasm과 모델이 APK 안에 들어 있음 |
| 한국어 음성 | TTS 플러그인으로 ko-KR 음성이 나옴 |
| 녹화 저장 | `/sdcard/Documents`에 저장 성공. 앱 전용 폴더 대체 경로는 쓰지 않았음 |
| 텔레메트리 | MediaPipe 1.2.3의 `odml.pa.googleapis.com` 로거는 fetch 래핑으로 막고, OS 수준에서는 INTERNET 권한이 없어 막힘 |

| 스쿼트 | 브라우저 | 5 | 5 | 통과 |

| 매달리기 | 브라우저 | — | 13.8초 | 기준값으로 사용. 사용자가 측정값을 신뢰하기로 함 |

누운 자세(푸시업)는 옆 바닥에서 찍으면 인식된다. 벤치프레스는 확인하지 못했다.

## 4. 측정하면서 고친 것

- **구간별 최소 시간 → 반복 전체 최소 시간(500ms)**: 실제 스쿼트에서는 150→100° 구간이 0.19~0.23초여서 정상 반복이 버려졌다.
- **재무장(armed)**: 가려졌다가 중간 자세에서 다시 보일 때 잘못 세는 것을 막았다.
- **네거티브**:
  - 바닥에 닿는 순간에 센다.
  - 양팔 평균 각도를 쓴다.
  - 기준은 100/140/95, 최소 250ms다.
- **준비 자세 보정 + 상대 판정 (스쿼트·푸시업·벤치)**:
  - 고정 각도 대신 각자의 준비 자세를 기준으로 삼는다.
  - 몸통 방향으로 준비 자세가 맞는지 확인한다.
  - 다음 반복을 세려면 재무장선을 다시 넘어야 한다.

## 5. 결정

- **WebView 유지**: S23 앱에서 GPU lite가 30fps, 24ms로 동작하고 정확도 기준도 통과했다. 그래서 MVP에서는 PoseSource를 네이티브 SDK로 바꾸지 않는다.
- **모델은 lite**: full은 미측정이다. lite로 정확도 기준을 통과했으므로 MVP 기본값은 lite다.
- **버전 고정** (package-lock 기준): `@mediapipe/tasks-vision` 1.2.3, Capacitor 8.6.2, TTS 플러그인 8.0.2, filesystem 8.1.5, keep-awake 8.0.1
