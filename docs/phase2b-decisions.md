# Phase 2b 진행 중 내린 판단

- 기간: 2026-11-23
- 브랜치: `feat/phase2b` (`feat/phase2a` 위, PR #12 병합 전)
- 계획: `docs/superpowers/plans/2026-11-23-phase2b-routine-app.md`
- 이 문서는 작업 중 진행 장부(git 제외)에 있던 판단 기록을 옮긴 것이다.

## 1. 사용자가 정한 것 (10.1절)
- backToReady 안내는 1번만 한다. 자세가 흐트러졌다가 다시 잡혀야 세트를 다시 시작한다.
- 세트마다 기록을 중간 저장한다.
- 앱이 백그라운드로 가면 자동으로 일시정지한다. 자동으로 다시 시작하지는 않는다.
- 일은 서브에이전트에게 맡기고, 실패하는 테스트를 먼저 쓴다.

## 2. 구현하면서 대신 내린 판단 (틀렸을 때의 비용)
| 판단 | 이유 | 틀렸을 때 |
|---|---|---|
| 자세가 400ms 동안 연속으로 흐트러져야 흐트러짐으로 친다 | 1프레임 깜빡임 때문에 반복이 다시 시작되는 것을 막는다 | 다시 시작이 0.4초 늦어진다 |
| 보정하는 운동은 신호가 minBaseline 아래로 내려가도 흐트러짐으로 친다(스쿼트는 무릎 150° 미만). `waitingForBreak` getter를 추가했다 | 안내를 듣고 그대로 스쿼트를 시작해도 다시 시작되게 한다 | — |
| ready가 null인 상태(상체가 잘림)도 흐트러짐으로 친다 | 상체가 잘린 배치에서 영원히 막히는 것을 막는다 | 기본값 보정이 반복될 수 있다 |
| SetRunner에 진행 중 `count`·`heldMs` getter를 추가했다 | snapshot에 진행 중인 값이 필요하다 | — |
| 쉬는 시간 계산을 하나로 합쳤다. 이름은 `setPhase`이고 `countdownRemainingMs`를 추가했다 | 중복을 없애고 화면에서 쓰기 위해서다 | — |
| style 검사 범위를 넓혔고, src에서 변수명 `style`을 금지했다 | CSP 때문에 인라인 스타일을 막는다 | 이름 짓기가 조금 불편하다 |
| 작업 6에 루틴 순서 변경과 App 화면 연결을 포함했다 | 설계 6.2-2에 있는데 계획에서 빠졌다 | — |
| 작업 8·9·11 구현자는 opus 모델로 했다 | 통합과 보안 위험이 크다 | 비용이 늘어난다 |
| 앱 의존성(MediaPipe·Capacitor 플러그인·Electron)은 시험용 앱과 같은 버전으로 선언만 했다. 모델 파일은 로컬에서 복사한다 | 새 다운로드를 하지 않기 위해서다 | — |
| visibility 자동 일시정지는 카메라가 켜진 동안에만 한다 | 권한 대화상자가 뜰 때 일시정지되는 것을 막는다 | — |
| useWorkout은 `{view, engine}`을 돌려주고, 첫 렌더에서는 둘 다 null이다. 엔진은 effect 안에서 만든다 | React StrictMode에서 안전하게 하려고 | — |
| 카메라 `<video>`를 늘 마운트해 두어서 쉬는 시간에도 카메라가 켜져 있다 | 운동마다 카메라를 다시 켜는 지연을 피한다 | 배터리를 더 쓴다(실기기에서 판단) |
| 카메라 오류 화면에 "홈으로" 버튼을 추가했다 | 다시 시도 말고는 빠져나갈 방법이 없었다 | — |
| PC 앱은 다운로드를 모두 취소한다 | 앱에 녹화 기능이 없다 | 나중에 내보내기 기능을 넣으면 다시 설계해야 한다 |
| PC 권한은 카메라(video)에 더해, 앱 origin의 `screen-wake-lock`만 예외로 허용한다 | 운동 중에 화면이 꺼지면 핵심 기능이 망가진다 | 권한 표면이 1개 늘어난다 |
| 한 번의 호출에서 나온 음성 문구를 모아 한 번에 말한다 | 앞 문구가 뒤 문구에 끊기는 문제를 막는다 | 문구가 길어지고, 다음 카운트가 그 문구를 끊을 수 있다 |
| 웹 음성은 `localService`인 한국어 음성만 쓴다 | 네트워크 요청 0건 원칙이다 | 로컬 한국어 음성이 없는 브라우저에서는 음성이 없다 |
| 기록 세트가 0개면 세션을 저장하지 않는다 | 빈 미완료 기록을 남기지 않는다 | — |

## 3. 나중으로 미룬 사소한 것
- 저장소
  - IndexedDB 열기에 실패하면 재시도가 안 된다.
  - 값이 같을 때 idb와 메모리 저장소의 정렬 순서가 다르다.
- 편집
  - 운동 행의 key가 인덱스라서, 순서를 옮기면 포커스가 따라가지 않는다.
  - 처리 중에 취소·삭제 버튼을 막지 않는다.
- 홈·기록
  - 오류 문구에 재시도 버튼이 없다.
  - 상세 화면에서 "오류"와 "없음"을 구분하지 않는다.
  - nextOrder를 늦게 읽는다.
- 엔진
  - 카메라 트랙이 끊겼을 때 다시 켜는 경로가 없다. **실기기에서 확인할 것**
  - 정상 종료 뒤 dispose가 마지막 음성을 끊을 수 있다.
  - 200ms마다 추가로 렌더된다.
  - 카운트다운에서 대기로 돌아오면 낡은 hint가 남을 수 있다.
- PC
  - `app://` 응답에 CSP 헤더가 없다(워커 CSP 빈틈. 지금은 워커를 쓰지 않는다).
  - Electron fuses를 설정하지 않았다.
  - 자가 점검이 CI에서 돌지 않는다.
- Android: CI가 만든 APK에는 모델 파일이 없다. 실기기에 설치할 때는 로컬에서 빌드한 APK를 쓴다.
